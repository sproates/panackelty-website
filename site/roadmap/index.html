Available now

Native alpha.14.

The developer preview combines exact arithmetic, checked domain types, namespaces and local packages with type-owned methods, a routed HTTP server framework, native HTTP clients and a static HTTP server tool. Compiler explanations expose more recorded checking decisions. Use the matching compiler, VM and standard library when running saved bytecode.

Native: 0.1.0-alpha.14 for Ubuntu 22.04+ x86-64 and macOS 14+ Apple silicon. Browser: separately pinned v0.2.1 with the alpha.14 compiler and no host filesystem, process or networking access.

What alpha.14 adds.

Alpha.14 brings type-owned methods and a routed HTTP server framework, with browsable API references and a playbook of runnable examples.

Released

Type-owned methods

Methods resolve through the receiver’s checked type, so APIs can share names without collisions. Dot-call syntax now uses explicit method ownership; the temporary migration arrows are gone.

Planned direction · not released

Alpha.15: strengthen the foundations.

Package management, compiler explanations and provenance, validated domain types, a library-boundary assessment, faster coverage and selected development improvements. A concrete test-speed milestone will improve local and CI feedback while preserving assertions and supporting stronger tests.

Package management is implemented and accepted on the next development branch for alpha.15. Dependencies can come from local folders, local archives, HTTPS archives or Git repositories pinned to a specific commit, with diagnostics that explain failures and how to resolve them. These additions are not yet released and are not included in the alpha.14 downloads.

Planned direction · not released

Alpha.16: build useful programs.

Typed HTTP exchanges between independent services, recursive file discovery, subprocess examples and a tiny build tool, with tested guides. These programs will exercise the foundations established in earlier releases. The build tool stays deliberately small. This release also includes an assessment of type inference and its diagnostics.

Planned direction · not released

Alpha.17: improve everyday development.

Basic support for one editor, source-aware runtime errors and Homebrew installation. The aim is to make programs easier to write, troubleshoot and install. A full language server and debugger are outside this scope.

Planned direction · not released

Alpha.18: interactive and connected applications.

Browser events invoking Panackelty handlers and bounded service/library contract testing. Contract design will follow concrete use cases. Versioned Docker toolchain images and Linux ARM64 releases remain optional.

Planned direction · not released

Alpha.19: improve language ergonomics.

Error-propagation shorthand and further guarded types, subject to design and evidence from real programs. This builds beyond alpha.15’s string constraints, collection sizes and cross-field record invariants. Targeted inference and library discoverability may support this release.

Target · not released

The first non-alpha release.

The alpha releases deliver capabilities in stages. The first non-alpha target brings those capabilities together into a coherent, tested and documented foundation for real applications. It includes the earlier release work; the remaining emphasis is integration, breadth and readiness. Detailed scope, version and date are still being defined.

Far off · research only

Ideas beyond the release plans.

These topics are far off and are not included in alpha 12, alpha 13, the first non-alpha target, or any other release plan. They are research and discussion topics only: scope, feasibility, implementation and timing are all undecided.

Research only · unscheduled

Foreign-function interface

Explore whether Panackelty should call foreign code, and what a safe boundary would require for types, effects, ownership, errors and supported platforms. No language, ABI or implementation is selected.

Research only · unscheduled

JIT compilation

Study whether measured performance needs could justify runtime native compilation while preserving exact language behavior. No compiler backend or release scope is selected.

Research only · unscheduled

Tracked concurrency

Explore how pure functions and an explicit model for effects and shared resources could prevent data races while enabling useful multi-core scaling. The concurrency model and its costs remain open questions.

Research only · unscheduled

Compile-time macros

Investigate whether compile-time code generation would solve demonstrated problems, and how it could preserve type checking, understandable diagnostics and reproducible builds. No macro system or syntax is selected.

Research only · unscheduled

Resource lifecycle types

Compare linear types and typestate as alternatives for compiler-tracking the lifecycle of external resources. No type model is selected.

A research topic is not a promise to build a feature or place it in a release. The roadmap records the open questions without scheduling implementation.
